# How to setup the development environment

1. Install [pnpm](https://pnpm.io/) and [rustup](https://rustup.rs/) (rustup installs the rust compiler and cargo, the rust package manager, for you)
2. Run `cargo install sqlx-cli` to install the [SQLx CLI](https://docs.rs/crate/sqlx-cli/latest), which is only needed to run the migrations. If you don't want to install the SQLx CLI, you can alternatively apply the migrations manually to the database by running the queries in [migrations/20260509173845_init.sql](./migrations/20260509173845_init.sql). (Note that you need to start the database first, which will be done in the next step.)
3. If you already have a PostgreSQL database running, use that database's connection URL in the configuration (in the next steps). If you do not have a PostgreSQL database running that the bot can use, use docker compose: `docker compose up -d`, which will start a PostgreSQL database in a container.
4. Copy `worker-config.example.json5` to `worker-config.json5` and fill in all the values in the config. If you are running the docker container for the database, you don't need to change the connection string. Otherwise, change `database_url` to the connection string. I recommend you to use `openssl rand -base64 64` to generate the `worker_api_token`.
5. Copy `api-config.example.json5` to `api-config.json5` and use the same `database_url`. Fill in all the fields accordingly and make sure to use **the same** `worker_api_token` as in the worker config and also generate a random cookie secret using `openssl rand -base64 64` (Note: You don't need to generate a new one if you are just running this inside a development environment. In production, make sure to have a different cookie secret.)
6. Add `http://localhost:5173/api/oauth/callback` as a redirect uri to your bot (in Fluxer).
7. Copy `.env.example` to `.env` and also fill in the values accordingly.
8. Finally, you can run `pnpm install:all` and then `pnpm dev` in the root of the project to start the bot. (Note that the API and worker might need some time to compile depending on your hardware, but it should not be more than a few minutes.) When the API is running, it will log "Now serving API", and when the bot (worker) is running, it will log "Logged in as ...!". Note that the dashboard (svelte) will hot-reload but the API and worker will not.
9. Go to [localhost:5173](http://localhost:5173) to access the dashboard.

Adminer is on http://localhost:8080/?server=db&username=botuser&db=rune_bot (password: `botpass`) if you started it using docker compose.
